# Contributing Guidelines for VizTR Meet

Thank you for your interest in contributing to **VizTR Meet**! This document provides guidelines for contributing to the project.

## Getting Started\n
Before contributing, make sure you have:\n\n* Python 3.10 or higher\n* Git\n* Basic understanding of the project's architecture (see [Architecture](docs/architecture.md))\n\n### Forking the Repository\n\n1. Log in to your GitHub account.\n2. Navigate to the [VizTR Meet repository](https://github.com/your-org/viztr-meet).\n3. Click the \"Fork\" button in the top-right corner.\n4. Clone your forked repository to your local machine:\n\n```bash\ngit clone https://github.com/your-username/viztr-meet.git\ncd viztr-meet\n```\n\n### Setting Up Your Development Environment\n\n1. Create a virtual environment:\n\n```bash\npython -m venv venv\nsource venv/bin/activate  # On Windows: venv\\Scripts\\activate\n```\n\n2. Install dependencies:\n\n```bash\npip install -r requirements.txt\n```\n\n3. Install the package in development mode:\n\n```bash\npip install -e .\n```\n\n## Making Changes\n\n### Branching Strategy\n\nWe use a standard fork-and-pull workflow.\n\n### Creating a Feature Branch\n\n1. Fetch the latest changes from the remote repository:\n\n```bash\ngit fetch origin\ngit checkout main\ngit merge origin/main\n```\n\n2. Create and switch to a new feature branch:\n\n```bash\ngit checkout -b feature/<feature-name>\n```\n\n### Making Changes\n\n1. Make your changes on the feature률이分支。\n\n2. Commit your changes with a clear commit message:\n\n```bash\ngit add <files>\ngit commit -m \"<descriptive commit message>\"\n```\n\n3. Push the branch to your forked repository:\n\n```bash\ngit push origin feature/<feature-name>\n```\n\n### Code Style\n\nThis project follows established Python code style guidelines.\n\n### Testing\n\nWe use pytest for testing. Ensure all tests pass before creating a pull request.

### Documentation\n\n* Update documentation as needed\n* Update API documentation\n* Add new examples if necessary\n\n### Creating a Pull Request\n\n1. Push your changes to your feature branch.\n\n2. Navigate to the [VizTR Meet repository on GitHub](https://github.com/your-org/viztr-meet).\n\n3. Click the \"Compare & pull request\" button.\n\n4. Fill out the pull request template:\n\n   * **Title:** A descriptive title\n   * **Description:** Detailed description of the changes, including motivation and context\n   * **Checklist:** Check the checklist at the bottom of the template\n\n5. Review and request changes if necessary.\n\n6. Merge your changes if all checks pass.\n\n## Setting Up Local Development\n\nThis project uses Docker for local development. To get started:\n\n1. Install Docker.\n\n2. Build the Docker image:\n\n```bash\ndocker build -t viztr-meet .\n```\n\n3. Run the Docker container:\n\n```bash\ndocker run -p 8000:8000 viztr-meet\n```\n\n## Testing in Docker\n\nYou can also run tests in Docker:\n\n```bash\n# Build the test image\ndocker build -t viztr-meet-test -f Dockerfile.test .\n\n# Run tests\ndocker run viztr-meet-test pytest\n```\n\n## Project Structure\n\n```\nviztr-meet/\n├── src/\n│   └── viztrmeet/          # Python package\n│       ├── core/           # Core components\n│       ├── routes/         # HTTP/WS endpoints\n│       ├── services/       # Provider interfaces\n│       └── main.py        # FastAPI entrypoint\n├── agent/                   # LiveKit integration\n│   ├── livekit_agent.py\n│   ├── requirements.txt\n│   └── .env.example\n├── tests/                   # Tests\n│   ├── unit/              # Unit tests\n│   └── integration/       # Integration tests\n├── docs/                    # Documentation\n│   ├── api.md\n│   ├── architecture.md\n│   └── development.md\n├── README.md              # Project README\n├── CONTRIBUTING.md        # Contribution guidelines\n├   LICENSE              # License file\n├── pyproject.toml        # Python packaging configuration\n└── .github/              # GitHub workflows\n    └── workflows/        # CI/CD pipelines\n```\n\n## Testing\n\n### Unit tests\n\nUnit tests are located in `tests/unit/` and test individual components:\n\n* `test_session.py` - Session management\n* `test_vad.py` - VAD processing\n* `test_providers.py` - Provider interfaces\n\nRun unit tests:\n\n```bash\npytest tests/unit/\n```\n\n### Integration tests\n\nIntegration tests are located in `tests/integration/` and test system interactions:\n\n* `test_api.py` - API endpoints\n* `test_session.py` - Session integration\n* `test_livekit.py` - LiveKit integration (if available)\n\nRun integration tests:\n\n```bash\npytest tests/integration/\n```\n\n### Performance tests\n\nPerformance tests are located in `performance/`:\n\n* `test_latency.py` - Latency testing\n* `test_throughput.py` - Throughput testing\n* `test_scalability.py` - Scaling testing\n\nRun performance tests:\n\n```bash\npytest performance/\n```\n\n### Code coverage\n\nThis project uses `coverage.py` for code coverage reporting:\n\n```bash\n# Run tests with coverage\npython -m coverage run -m pytest tests/\n\n# Generate coverage report\npython -m coverage report\n\n# Generate HTML coverage report\npython -m coverage html\n```\n\n## Deployment\n\n### Docker deployment\n\nBuild and run the application with Docker:\n\n```bash\n# Build the Docker image\ndocker build -t viztr-meet .\n\n# Run the application\nDOCKER_BUILDKIT=1 docker compose up --build\n```\n\n### Kubernetes deployment\n\nDeploy to Kubernetes:\n\n```yaml\n# kustomization.yaml\napiVersion: kustomize.config.k8s.io/v1beta1\nkind: Kustomization\n\nresources:\n  - deployment.yaml\n  - service.yaml\n  - hpa.yaml\n\nconfigMapGenerator:\n  - name: viztr-meet-config\n    files:\n      - .env\n\nsecretGenerator:\n  - name: viztr-secrets\n    literals:\n      - WS_AUTH_SECRET=your-secret-key\n```\n\n### Cloud deployment\n\nDeploy to major cloud providers:\n\n* **AWS:** ECS/EKS\n* **Google Cloud:** Cloud Run\n* **Azure:** Azure Container Instances\n* **DigitalOcean:** App Platform\n\n## Troubleshooting\n\n### Common issues\n\n| Problem | Solution |\n|---------|----------|\n| \"ModuleNotFoundError: No module named viztrmeet\" | Ensure the package is installed with `pip install -e .` |\n| \"Connection refused\" | Check if the application is running and port is available |\n| JWT token validation errors | Verify the secret key matches the one in .env |\n| VAD model download failures | Check internet connection and model availability |\n\n### Getting help\n\n* GitHub Issues: https://github.com/your-org/viztr-meet/issues\n* Discord: https://discord.gg/viztr-meet\n* Email: support@viztr-meet.com\n\n## Contributing\n\nThis project welcomes contributions!
